# Staged exact-source collector helper

The helper reads only a supervisor-supplied absolute file path for an expected conversation. It has an empty inherited environment, private bounded stdin/stdout IPC, no lease or socket capability, and its own controller-owned process group. One request can be in flight; each response and request is capped at 65,536 bytes. File reads are limited to 256 KiB per request, incomplete lines are retained, and one raw record is capped at 32 MiB.

Only assistant records with matching sessionId and isSidechain=false contribute. Explicit sidechains and non-assistant metadata do not contribute. A malformed/foreign assistant freezes the retained partial prefix. Equality for duplicate message.id/requestId keys means exact equality of the five counted normalized components, including unknowns and cache subsets; excluded auxiliary metadata is not compared or counted. A differing counted value freezes before mutation with conflicting_usage_record. This is not certification of last-wins semantics or complete native usage.

The single existing accumulator enforces both 65,536 identities and 16 MiB charged key/value storage. There is no second identity map or probabilistic fingerprint. Verified inode replacement, observed truncation, or same-length modification starts a bounded rebuild. The controller retains prior usage during rebuilding and refuses candidates below a previously known component watermark. Missing/nonregular files and read failures produce retryable diagnostics on the same pinned path. EOF is caught_up only, never accounting completion. Source revision is None and freshness remains uncertain.

Cancellation signals the owned PGID before reaping its leader. Waiting uses the supplied absolute deadline. Drop reuses an explicit deadline, or allows at most 100 ms when no caller deadline was supplied. Stopped-process fixtures prove nonblocking advance, bounded cancellation/Drop, and owned PID/PGID absence. No hard guarantee about kernel-uninterruptible I/O is claimed. This unit does not wire provider admission, report publication or native finalization; those are coordinated separately.

Evidence: 01 is a compiling helper-skeleton RED with 4 failing tests; 02 has the first 4 real helper tests passing; 03 is a distinct concurrent receiver compile failure, not a behavioral regression. 04 passes 10 helper tests. 05 passes all 13 helper/file/process tests including both production index caps, the raw record cap and an environment-clearing probe. 06 records an unrelated receiver-test clippy warning; 07 passes all 10 pure tests; 08 passes owned lib/helper clippy with warnings denied; 09 passes owned formatting. Commands, counts and exits are retained in the separate logs.

No live provider run was used for this helper acceptance. Complete accounting, certified final source completion, and 50-session/platform acceptance remain separate gates.
