## What to build

Resolve the native facts that gate the agreed macOS Bridge before dependent implementation: stable signed identity and updates, native permission/settings behavior, safe CLI/Server compatibility, and original bundled sound provenance and supported native sound requirements. Deliver an evidenced go/no-go result for the path from installation and opt-in to a native OVRCR banner and callback. This is a verification-only enabling slice, not a production Bridge implementation. Read-only investigation can start immediately; executable native probes or shared permission changes require explicit authorization and disposable task-owned resources. Keep the Dashboard as alert decider, Server as sole session/process owner, and Bridge as display/activation adapter; do not substitute a different product contract when a fact fails.

## Acceptance criteria

- [ ] Record primary-source and, where authorized, native evidence for a stable signed Dock-less application identity, installation/update behavior, permission request/status, explicit documented System Settings opening with manual Notifications → Bridge instructions and native click callback; distinguish observed results from unverified claims.
- [ ] Establish how the CLI/Server and stable separately updated Bridge can detect incompatible versions and fail visibly without Script Editor fallback, stale-target navigation or a second Server/Dashboard; record the compatible contract for later slices, not a speculative general compatibility framework.
- [ ] Establish source/provenance, supported format, duration, bundled-resource lookup and native playback requirements for original bundled short tones and system-default banner sound. Reuse attributed native evidence for the same named/default notification API where applicable, clearly distinguishing it from unperformed playback of the new originals. Do not reintroduce independent macOS playback or bypass notification policy. Full production selector/audio acceptance belongs to #224 and installed-release acceptance to #226.
- [ ] For an authorized disposable native probe, demonstrate the bounded install/opt-in/banner/callback path and permission identity across an ordinary CLI rebuild; otherwise identify the exact blocked evidence rather than claiming feasibility. Preserve screenshots/accessibility evidence where relevant and verify only task-owned cleanup.
- [ ] Publish the findings for dependent tickets. Each unresolved fact has a precise blocker and next verification action; a conflict with the agreed contract remains blocking until resolved. No feature implementation, production Bridge replacement, user-config modification or parent-issue edit occurs in this verification slice.
