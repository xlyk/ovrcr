## Decision and finite stopping point

The narrow trace improves the previous blocker: same-ID paginated revert is an unload/CAS/reload operation with a source-visible shutdown hook opportunity; deprecated rollback rejects paginated; the actual native previous-prompt action forks and unsubscribes. The reproduced fork leaves an explicit gap between UI selection and next-turn startup. An exact-path poller cannot close that gap using unchanged old-file identity, and a supplied-old-thread metadata query answers a different question.

Thus the source gate remains BLOCKED under the current continuous exact-current-conversation requirement. A future design could explicitly choose a fixed original-thread scope or accept next-work-only invalidation, but neither scope change is authorized by this note.
