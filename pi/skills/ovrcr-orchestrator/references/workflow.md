# Requested Pocock workflow

Read this reference only for the explicitly requested full workflow or a named
phase. Direct delegation uses [delegation.md](delegation.md) without stage skills.
The installed procedures remain the source of their gates/templates; read each
when entering its phase instead of copying or rewriting it.

Recover the requested endpoint, existing approvals and artifact revisions first.
A request for a local spec ends there; it does not authorize implementation or
tracker publication. Preserve previously supplied authority within its scope.

Choose the entry from existing evidence, not from a fixed first stage:

- An idea enters its requested grilling/spec/tickets/implementation sequence.
- An existing spec enters Tickets when the requested breakdown is not yet approved.
  Read the original spec and its comments; reuse confirmed understanding/test seams
  whose scope still matches. Return only unresolved decisions to their real gate.
- Approved tickets enter Implement. Read their canonical bodies, parent/spec and
  blocking edges; do not re-interview or republish an approved graph after compaction.
- A direct request stays in direct mode, including a direct independent review.

| Requested phase | Procedure and completion |
| --- | --- |
| Grill | Read the chosen grill-me/grill-with-docs wrapper and underlying grilling procedure. Investigate facts; keep decisions with the parent/user. Use grill-answer-sheet for every round. Complete the procedure's shared-understanding confirmation. |
| Spec | Read installed to-spec and its template. Synthesize agreed behavior against actual code and confirmed test seams. Preserve unresolved decisions; publish only within scope. |
| Tickets | Read installed to-tickets. Create verifiable slices and genuine blockers. Preserve the procedure's granularity/dependency approval and publish approved tickets once using the configured tracker. |
| Implement | Read installed implement, tdd and code-review procedures. Apply [implementation.md](implementation.md) through bounded managed children and the actual review capabilities. Validate the integrated revision. |

If a requested stage procedure is missing, report that phase's dependency gap;
continue useful preparation within scope. This does not block supported direct
research/review/coding or authorize installing/modifying unrelated skills.
No native Skill tool is assumed: read the actual procedure through the available
file/tool surface and preserve its invocation policy.

The shared-understanding confirmation, proposed test seams and numbered ticket
breakdown/granularity/dependencies are real decision gates. Link a valid prior
confirmation to its original question/artifact and scope. A recommendation, silent
default, timeout or condensed continuation note is not that confirmation. Spec is
synthesis, not a second interview. Preserve to-spec's actual template/triage rule
and to-tickets' vertical slices (or its expand–contract exception for a wide refactor).

The parent schedules eligible assignments and required independent review. Workers
implement/check/self-review; native helpers do not replace the parent's review
assignments. Current coding children cannot commit; retain an authenticated complete
snapshot and leave any authorized repository commit to the delivery owner. Preserve
the installed method's outcomes while respecting actual task permissions.

Use the repository's configured tracker only when publication is requested. OVRCR
uses GitHub through git/gh. A workflow index is not a tracker mirror or scheduler.
Before publication retain the approved local body, parent reference, blockers and
requested action in the existing workflow record. Publish blockers before their
dependents, retaining each canonical URL/native blocking relationship as it returns.
Do not close or modify the source parent merely because tickets were published.

If a tracker command times out, loses its reply or otherwise has an uncertain
outcome, inspect that configured tracker's existing issues before retrying. Match
the original approved title/body, parent and blockers, including closed issues.
One attributable match supplies its canonical reference; record it and skip another
create. Ambiguous or unverifiable publication stays an explicit gap. Resume from
that gap without treating an empty local index as proof nothing was published.
Before a successor runs, its required predecessor behavior must be accepted and
present in the actual assigned base. Ready/labels/commits alone do not prove that.
Declare the approved graph through ovrcr_dependencies. Select authenticated accepted
outputs/reviews and verify the actual pinned successor base or explicitly permitted
complete input baseline. Common Prepare/Launch/SendInitial gates own admission;
the stage coordinator does not add a scheduler or dependency store.

At a phase change preserve original decisions/spec/ticket sources and refresh the
one continuation note. For changed requirements, version the brief and identify
affected acceptance/dependents; preserve independent work and valid approvals.
Use the existing assignment Followup version/identity/control epoch and dependency
graph revision tools. Give active children an explicit revised brief. A new contract,
candidate, review round or context selection requires current evidence; old Passed
reports never silently satisfy changed work. Revisit confirmed seams/breakdown only
when the changed scope actually affects them.

Before delivery name the actual integrated revision and run its required checks,
including repository native/provider gates when applicable. Keep named worker checks,
independent axes and integrated validation distinct. Per-ticket passing summaries do
not prove an integrated feature. Retain gaps and original command/outcome evidence in
the workflow record, and apply the user's actual push/PR/merge authorization.
Stop at the requested endpoint. Completion never grants push, merge or deployment.
