# Requested Pocock workflow

Read this reference only for the explicitly requested full workflow or a named
phase. Direct delegation uses [delegation.md](delegation.md) without stage skills.
The installed procedures remain the source of their gates/templates; read each
when entering its phase instead of copying or rewriting it.

Recover the requested endpoint, existing approvals and artifact revisions first.
A request for a local spec ends there; it does not authorize implementation or
tracker publication. Preserve previously supplied authority within its scope.

| Requested phase | Procedure and completion |
| --- | --- |
| Grill | Read the chosen grill-me/grill-with-docs wrapper and underlying grilling procedure. Investigate facts; keep decisions with the parent/user. Use grill-answer-sheet for every round. Complete the procedure's shared-understanding confirmation. |
| Spec | Read installed to-spec and its template. Synthesize agreed behavior against actual code and confirmed test seams. Preserve unresolved decisions; publish only within scope. |
| Tickets | Read installed to-tickets. Create verifiable slices and genuine blockers. Preserve the procedure's granularity/dependency approval and publish approved tickets once using the configured tracker. |
| Implement | Read installed implement, tdd and code-review procedures. Apply [implementation.md](implementation.md) through bounded managed children and the actual review capabilities. Validate the integrated revision. |

If a requested stage procedure is missing, report that phase's dependency gap;
continue useful preparation within scope. This does not block supported direct
research/review/coding or authorize installing/modifying unrelated skills.
No native Skill tool is assumed: read the actual procedure through the available
file/tool surface and preserve its invocation policy.

The parent schedules eligible assignments and required independent review. Workers
implement/check/self-review; native helpers do not replace the parent's review
assignments. Current coding children cannot commit; retain an authenticated complete
snapshot and leave any authorized repository commit to the delivery owner. Preserve
the installed method's outcomes while respecting actual task permissions.

Use the repository's configured tracker only when publication is requested. OVRCR
uses GitHub through git/gh. A workflow index is not a tracker mirror or scheduler.
Before a successor runs, its required predecessor behavior must be accepted and
present in the actual assigned base. Ready/labels/commits alone do not prove that.

At a phase change preserve original decisions/spec/ticket sources and refresh the
one continuation note. For changed requirements, version the brief and identify
affected acceptance/dependents; preserve independent work and valid approvals.
Stop at the requested endpoint. Completion never grants push, merge or deployment.
