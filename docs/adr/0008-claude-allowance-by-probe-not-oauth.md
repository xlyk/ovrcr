# Claude allowance comes from a consented probe, not from an OAuth read

Decided 2026-10-01, from the usage-defaults grilling (item 4). The probe shipped as `quota.claude.probe` (off by default) with `QuotaSource::Probe`; the decision is unchanged.

Claude Code publishes subscription allowance only through its status line, and only after a session's first API response, so a fresh OVRCR launch showed nothing for Claude. Other tools (oh-my-pi, Superset, CodexBar, claudebar) read the Claude Code OAuth token from the Keychain or `~/.claude/.credentials.json` and call the undocumented `api.anthropic.com/api/oauth/usage` endpoint. OVRCR does not. Anthropic's published guidance (code.claude.com, "Authentication and credential use", read 2026-10-01) says OAuth is intended exclusively for ordinary use of Claude Code and native Anthropic applications, that developers may not collect, store or intermediate Claude.ai credentials or session tokens, and that enforcement may come without notice. The endpoint is undocumented and informational. Neither fact makes the read certainly prohibited for a local tool on the user's own machine, and neither makes it approved; OVRCR declines to build on that uncertainty while a documented route exists.

The documented route is a quota probe: when `quota.claude.probe` is on and no managed Claude session has reported inside the stale boundary, the Server runs the unmodified `claude` binary in a PTY in an OVRCR-owned empty directory with OVRCR's own status line supplied through `--settings`, the cheapest model, no tools, and a one-word prompt; the status-line callback carries the account's `rate_limits`; the Server then ends the process. The probe is hidden (never a Session), runs on attach when stale, on manual refresh, and at most every 30 minutes while a Dashboard is attached with no live report. It spends one small prompt per run and leaves a conversation in Claude's own history; the setting's description says both. OVRCR accepts Claude's folder-trust dialog once for that empty directory and for no other. This reverses the earlier rule in `provider-usage-spec.md` that OVRCR issues no prompt to obtain quota; that rule is kept for every unconsented path.

Under every route OVRCR reads no Claude credential, never refreshes, copies, persists or logs a token, and keeps no account identifier from `claude auth status`, which it uses only for the signed-in and plan state.

Re-check this decision when Anthropic documents a usage API for subscribers or changes the credential guidance.
