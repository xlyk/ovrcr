# Hosted Linux capacity acceptance

The `linux capacity` CI job runs the existing ignored
`fifty_session_reporting_capacity` integration test alone on an Ubuntu runner.
It enables `acceptance-diagnostics`, selects the test by its exact name, and uses
`--ignored --exact --nocapture`. The job does not configure provider credentials
or start a paid native provider session.

The test retains its original acceptance limits: 50 sessions, 600 reports per
session over 60 seconds, 3,000 rejected stale reports, five failed collectors,
control latency below 250 ms at p99 and below one second at maximum, and sampled
process-tree RSS growth below 3 GiB. It also asserts the existing accounting,
collector IPC, dispatcher, raw-event, dashboard, cross-session, and owned-process
bounds.

Every run uploads `linux-capacity-<run>-<attempt>` even when the test fails. The
artifact contains raw test stdout in `test.log`, its exit status in `test.exit`,
and the CSV files generated by the test under `load/`, including resources,
latency, accounting, queue snapshots, collector snapshots, and owned PIDs. It
also records `uname`, verbose Rust compiler information, Cargo version,
`/proc/meminfo`, and Linux `somaxconn` so the host, memory sample, toolchain, and
kernel listen-backlog setting remain attributable.

This job supplies an isolated hosted Linux capacity attempt. A green workflow
still proves only the assertions and sampled measurements in this test. It is not
a full heap maximum, a provider-accounting completeness result, or native macOS
acceptance.
