# OVRCR MVP Implementation Plan

> **Execution:** Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`. Complete the checked steps in order.

**Outcome:** A macOS/Linux terminal multiplexer that groups up to 50 coding-agent sessions by Git project and worktree, keeps them alive while the dashboard is detached, and renders one selected PTY.

**Design:** One Rust binary runs as a CLI, synchronous server, or Ratatui dashboard. The server owns worktrees, PTYs, process groups, and live terminal state. Clients use a framed Unix socket; TOML stores projects and OVRCR-owned workspaces.

**Stack:** Rust 2024, Clap, Ratatui, Crossterm, portable-pty, vt100, Serde, TOML, Bincode, libc, anyhow, and tempfile.

**Source spec:** `docs/superpowers/specs/2026-09-04-ovrcr-mvp-design.md`

## Product constraints

- Target macOS and Linux with blocking I/O and threads. Do not add an async runtime.
- Support and test 50 lightweight sessions, one dashboard, and concurrent short-lived control clients.
- Manage only OVRCR-registered projects and OVRCR-created workspaces and sessions.
- Use Git as the worktree authority, TOML as the ownership registry, and memory for live sessions.
- Render one selected terminal. Show `ctx -`; use `Ctrl-g` to leave terminal mode.
- Omit split panes, copy mode, historical scrollback, pause, inferred agent state, context accounting, command palette, terminal mouse forwarding, and sidebar resizing.
- Pass Git and session arguments directly to child processes. Never invoke them through a shell.
- Run every destructive-operation safety check required by the spec.
- Prefix every executable and pipeline stage with `rtk`.

## Task completion rules

- For core behavior, write the smallest failing test, implement enough to pass it, and stop.
- Prefer happy-path integration tests. Add another test only for a reproduced bug, explicit requirement, or destructive-operation safety check.
- Skip coverage targets, property tests, fuzzing, snapshot suites, and equivalent-case matrices.
- Before committing, run `rtk cargo fmt --check`, `rtk cargo check --all-targets`, and the task's named tests. Fix only task-related failures.
- Early internal tasks may lack a usable interface, but every completed task must compile cleanly.
- Merge only completed tasks into `main`. After a usable path exists, preserve it in every later task.
- Prioritize a usable MVP over additional tests.

## Orchestrator workflow

- Run tasks in order. Start the next task only after the current PR passes review and its completion gate, then merges into `main`.
- Create each task's worktree from the latest `origin/main`. Give the worker its worktree, branch, file boundary, outcome, named tests, exclusions, and the complete Worker rules below.
- Track task, worker, worktree, branch, current step, evidence, blocker, commit, and PR URL in a compact ledger.
- Require evidence at RED, GREEN, and PR-ready. A changed file, test result, commit, or PR counts; commentary alone does not.
- After 10 minutes without evidence, excluding an active build or test, ask for the current command and blocker. After the same approach fails twice, interrupt and simplify or reassign.
- Raise material risks immediately with `CONCERN:`, followed by the problem, impact, and needed decision.
- Review only the task diff, requirements, and completion gate. Reject unrelated changes, future abstractions, new dependencies, and excess tests.
- Verify the worktree, commit, push, and PR before accepting `TASK_DONE`. After merge, verify `main`, retire the worktree, and dispatch the next task.

## Worker rules

- Work only in the assigned worktree and branch, never on `main` or another task's worktree.
- Read the source spec, Product constraints, Task completion rules, these rules, and the assigned task. Do not implement subsequent tasks.
- Stay within the task's file list. Raise `CONCERN:` before touching another file.
- Use the smallest RED → GREEN cycle and only the named tests. Skip speculative features, dependencies, abstractions, refactors, cleanup, documentation, and test matrices.
- Report RED, GREEN, PR-ready, or `TASK_BLOCKED`. After the same approach fails twice, stop and report the commands, error, and smallest next move.
- Run the completion commands, stage only task files, commit, push, and create the PR. Do not merge unless assigned.
- Finish only after the push and PR succeed. Return `TASK_DONE`, task title, absolute worktree, branch, full commit SHA, PR URL, and command results.

```rust
#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct Registry { pub projects: Vec<ProjectRecord> }

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct ProjectRecord {
    pub name: String,
    pub repo: PathBuf,
    pub workspace_root: PathBuf,
    #[serde(default)]
    pub workspaces: Vec<WorkspaceRecord>,
}

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct WorkspaceRecord { pub name: String, pub path: PathBuf, pub branch: String }

pub struct RegistryPath(pub PathBuf);

impl RegistryPath { pub fn resolve() -> anyhow::Result<Self>; }
impl Registry {
    pub fn load(path: &Path) -> anyhow::Result<Self>;
    pub fn save_atomic(&self, path: &Path) -> anyhow::Result<()>;
    pub fn project(&self, name: &str) -> anyhow::Result<&ProjectRecord>;
    pub fn project_mut(&mut self, name: &str) -> anyhow::Result<&mut ProjectRecord>;
    pub fn workspace(&self, project: &str, workspace: &str) -> anyhow::Result<&WorkspaceRecord>;
    pub fn add_project(&mut self, project: ProjectRecord) -> anyhow::Result<()>;
    pub fn remove_project(&mut self, name: &str) -> anyhow::Result<ProjectRecord>;
    pub fn add_workspace(&mut self, project: &str, workspace: WorkspaceRecord) -> anyhow::Result<()>;
    pub fn remove_workspace(&mut self, project: &str, workspace: &str) -> anyhow::Result<WorkspaceRecord>;
}
```

`RegistryPath::resolve` honors `OVRCR_CONFIG`, otherwise uses `ProjectDirs::from("", "", "ovrcr")`. `load` returns empty only for a missing file. `save_atomic` writes and syncs a temporary file in the same directory, renames it, then syncs the parent directory on Unix.

Accept nonempty names containing ASCII letters, digits, `.`, `_`, and `-`. Reject separators, `..`, duplicate projects, duplicate workspaces within a project, and project removal while workspaces remain.

```rust
}
```

```rust
pub enum SessionPhase { Running, Exited { code: Option<u32>, signal: Option<String> } }

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct SessionSummary {
    pub id: SessionId, pub project: String, pub workspace: String,
    pub name: String, pub label: String, pub pid: Option<u32>,
    pub started_unix_ms: u64, pub phase: SessionPhase,
}

#[derive(Clone, Debug)]
pub enum SessionEvent {
    Output { id: SessionId, bytes: Vec<u8> },
    Exited { id: SessionId, phase: SessionPhase },
}

impl Session {
    pub fn spawn(id: SessionId, spec: SessionSpec, size: TerminalSize, events: Sender<SessionEvent>) -> anyhow::Result<Arc<Self>>;
    pub fn summary(&self) -> SessionSummary;
    pub fn write(&self, bytes: &[u8]) -> anyhow::Result<()>;
    pub fn resize(&self, size: TerminalSize) -> anyhow::Result<()>;
    pub(crate) fn apply_output(&self, bytes: &[u8]);
    pub fn current_screen(&self) -> Vec<u8>;
    pub fn terminate(&self, grace: Duration) -> anyhow::Result<()>;
    pub fn wait_until_exited(&self, timeout: Duration) -> anyhow::Result<SessionPhase>;
}
```
