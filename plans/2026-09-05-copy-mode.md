# Keyboard Copy Mode Implementation Plan

> **For agentic workers:** Use the `executing-plans` skill to implement this plan task by task. Steps use checkbox syntax. This document is planning only; execution, commits, and delegation require a separate execution request.

**Goal:** Select terminal text with the keyboard and send the selected plain text to the dashboard terminal's clipboard.

**Architecture:** The dashboard owns an immutable, session-scoped copy snapshot while its existing parser continues consuming live output. The first deliverable copies the current screen without changing the server or socket protocol. A separately gated integration task extends selection into the immutable snapshots proposed by historical scrollback.

**Tech Stack:** Rust 2024; existing Ratatui 0.30, Crossterm 0.29, and vt100 0.16; enable Crossterm's existing `osc52` feature. Blocking I/O and the existing dashboard event loop remain in place.

**Spec:** The copy-mode checkbox in `README.md`; architectural constraints from `plans/2026-09-04-ovrcr-mvp-design.md`; proposed history API in `plans/2026-09-05-historical-scrollback.md`.

**Status:** Proposed design and defaults, not an approved specification or implemented behavior. The MVP design explicitly deferred copy mode. No implementation tests were run to produce this document.

## Proposed interaction and boundaries

| Action | Default |
|---|---|
| Enter copy mode | `[` in Browse; from Terminal use existing `Ctrl-g`, then `[` |
| Move cursor | arrows or `h/j/k/l`; movement clamps to snapshot bounds |
| Row boundaries | `Home`/`0` to first cell; `End`/`$` to last cell |
| Snapshot boundaries | `g` to first cell; `G` to last cell |
| Anchor selection | Space or `v`; pressing again resets the anchor to the cursor |
| Copy | `y` or Enter sends the anchored inclusive range; without an anchor, show `Set an anchor with Space` |
| Exit | Escape, `q`, or `Ctrl-g` returns to Browse without sending PTY input |

Entry starts the copy cursor at the captured terminal cursor, normalized to the leading cell of a wide character. Selection is linear, inclusive at both endpoints, and works in either direction. Movement steps by terminal cells, skipping wide continuations; the complete vt100 cell string, including combining marks, is atomic. Do not invent a new Unicode layout engine: copying matches what vt100 renders, including its existing limitations for complex emoji clusters.

Copy freezes displayed content and selection, not the child process. Continue reading output, handling `ScreenDirty`, and updating the live parser. After successful OSC52 emission, remain in copy mode so the selection remains available if the terminal ignores the request. The status is `Clipboard request sent; paste to verify`, never an unverified `Copied` claim. The user exits explicitly.

Resizing to different pane dimensions cancels copy with `Copy cancelled: terminal resized`, then follows existing resize behavior. This deliberately avoids adding a second viewport or reflow model. A selected-session change, removal of that session, or dashboard disconnect also ends copy; same-session screen resynchronization does not. Copy of an exited session's retained final screen is allowed. A new dashboard starts in Browse and captures fresh state.

Alternate-screen entry captures only that visible screen. If the child changes screens during selection, the frozen copy remains visible until exit; the live parser follows the child. Do not merge primary and alternate screens or infer erased text. OSC52 emitted by child output must never become a clipboard action; only a user copy key creates that action.

Plain-text extraction preserves explicit spaces and combining marks, omits unused trailing blank cells, expands terminal-rendered tabs to spaces, joins soft wraps, and inserts `\n` at hard row boundaries. Selecting a trailing newline requires selecting into the following row. The source is the snapshot's text cells, never its formatted ANSI bytes. Cap the UTF-8 payload at 64 KiB; reject oversize or empty selections without emitting a clipboard sequence. No clipboard reads, support probing, command fallback, automatic save-to-file, mouse selection, rectangular selection, search, word motions, or configurable bindings.

Declare `pub mod copy;` inside `src/tui.rs`; the nested module keeps selection and clipboard helpers out of the already-large UI file. Define these proposed interfaces in `src/tui/copy.rs`:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub struct CopyPoint { pub row: u16, pub col: u16 }

pub struct CopySelection {
    pub session: SessionId,
    pub screen: vt100::Screen,
    pub cursor: CopyPoint,
    pub anchor: Option<CopyPoint>,
}

#[derive(Clone, Copy)]
pub enum CopyMotion { Left, Right, Up, Down, RowStart, RowEnd, First, Last }

impl CopySelection {
    pub fn capture(session: SessionId, screen: &vt100::Screen) -> Self;
    pub fn move_cursor(&mut self, motion: CopyMotion);
    pub fn set_anchor(&mut self);
    pub fn selected_text(&self) -> Option<String>;
    pub fn contains(&self, point: CopyPoint) -> bool;
}
pub const MAX_COPY_BYTES: usize = 64 * 1024;
pub fn write_clipboard(writer: &mut impl std::io::Write, text: &str)
    -> std::io::Result<()>;
```

Add `InputMode::Copy`, `DashboardAction::CopyText(String)`, `Dashboard::copy: Option<CopySelection>`, and `Dashboard::copy_notice: Option<String>`. Keep `mode == Copy` exactly when `copy.is_some()`; cancellation resets both together. Add private `screen_session: Option<SessionId>` and `pending_screen: Option<(SessionId, u64)>` to distinguish the displayed session from a selection awaiting a screen response. Add `cancel_copy(&mut self, notice: Option<&str>)`, returning to Browse and dropping the snapshot, and `finish_copy(&mut self, result: std::io::Result<()>)`, preserving the selection and setting a sent/error notice.

These fields describe the current single-view client. Split-pane integration must store each copy snapshot with the pane's session and view generation; it must not select a different pane's global parser. The local readiness fields are not a substitute for the split-pane plan's proposed protocol revisions.

## Acceptance and review checklist

- [ ] Current-screen copying works with arrows/hjkl, forward/reversed ranges, wide and combining text, explicit spaces, hard newlines, and soft wraps; viewport padding and terminal control sequences do not leak into clipboard text.
- [ ] Output and resynchronization continue while the selected screen stays frozen. Selection change, removal, resize, and disconnect cannot reuse a stale copy selection. Exited screens remain selectable; reattach creates fresh state.
- [ ] Copy keys, paste, and mouse input never reach the child in Copy mode. Existing Terminal mode and Ctrl-g behavior remain intact.
- [ ] Literal Ratatui geometry remains unchanged. Highlight covers both columns of a wide glyph, and tiny panes do not panic.
- [ ] The clipboard payload is bounded and only emitted after an explicit copy key. I/O and payload errors keep the selection. An OSC52 write is described as a request, with real paste verification reported separately.
- [ ] Task 6 is reported independently. Until its dependency and tests pass, describe the feature as current-screen copy mode and do not claim historical selection.

**Main risks:** vt100's terminal-cell semantics bound Unicode fidelity; formatted-screen reconstruction must retain wrapping; OSC52 support depends on the actual outer terminal; request readiness must not accidentally replace a frozen selection; the history and split-pane plans may rename proposed interfaces before implementation. Resolve these with the focused behavioral checks above, not new persistence or abstraction layers.
